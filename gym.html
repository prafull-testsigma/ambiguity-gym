Ambiguity Gym

Every control here is deliberately ambiguous, so the agent has to stop and ask. What it asks — and with which reason — is the thing under test.

state is per page load

1 · data

Three things are called Hyderabad. Only a person knows which was meant.

2 · locator

Four buttons read Continue. Nothing on the page says which one advances the booking.

3 · input

Values nobody supplied. The agent must not invent them.

4 · missing

There is no "random world text" anywhere on this page, and no near-miss to tempt a wrong click. Asking for it must produce reason missing with no options — which is what offers "Record it".

5 · record it

A drag handle with no accessible name and no click target. The agent cannot do this; a person demonstrates it while the recorder watches.

6 · many choices

Twelve near-identical fares. Forces a question with more options than fit comfortably — use this to test long choice lists and keyboard navigation.

7 · many fields

One instruction ("fill the passenger address") has to become several actions. Use this to check that sub-actions appear one by one under a single step.

8 · slow

The seat map button does not exist for the first 8 seconds. Tests waiting, retrying, and what the panel shows while nothing is happening.

seat map loading…

9 · flaky

Fails the first two attempts with a visible error, succeeds on the third. Tests retry behaviour and what a mid-run failure looks like.

10 · gated

Payment is disabled until the terms box is ticked. Tests preconditions — the agent must notice the gate rather than report a dead end.

11 · long list

Forty passengers, all similar. Use with a step per row to produce a long run — for scroll, "go to bottom", and long-transcript testing.

12 · onward

A second page, for navigation and re-grounding steps.
